3 of Spades — Fix Plan Overview

8 changes across the 2_deck_fixes.md spec. Let's review scope and clarify the ambiguous ones before writing the plan.

🔴 Architecture Changes (high impact)
1. Card Identity — deckColor

Add deckColor: "red" | "blue" to every Card object. Affects deck.ts, GameState, hands, tricks, partner logic, bot engine, socket payloads, UI rendering. Propagates everywhere.

2. Partner Selection — exact physical card

Bid winner picks exact copy (red_spades_K vs blue_spades_K). If bidder holds one copy, they can pick the other. UI shows both copies as separate selectable items. Backend validates by exact card ID.

3. Partner Reveal — exact ID match only

Currently both copies of a card trigger reveal. New rule: only the exact selected card reveals a partner. The other copy (same rank+suit, different deck) is just a normal card.

4. Remove 3♠ Supreme Priority

Currently 3♠ auto-wins every trick. New rule: 3♠ is a normal card with rank "3" (lowest rank). It keeps its 30-point value but has no special trick-winning power.

5. Trick Winner — last duplicate wins

When two identical cards are played (double deck), currently the first one wins. New rule: the last played duplicate wins. e.g. A♠ then A♠ → second player wins.

🟡 UI / Layout Changes
6. Player Position Sync — fixed absolute seats

Currently each player sees themselves at the bottom (relative view). Spec says: ALL players must see the SAME table layout. Seat 0 is always at Bottom, Seat 1 always Left, etc. "You" label just highlights your seat.

7. Winner Dialog — scrollable

The game-end dialog cuts off on small screens. Add max-height: 90vh + overflow-y: auto so leaderboard and buttons are always reachable.

🟢 Already Partially Done
8. Score Persistence Between Rounds

The spec says "Play Another Round" was wiping scores. We already implemented cumulative per-player scoring and round continuation. This needs verification + any gaps filled.
