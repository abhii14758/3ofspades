Animation Approach — GSAP vs Framer Motion

The codebase currently uses Framer Motion. Where should GSAP be added?

A

GSAP for new animations only

Keep existing Framer Motion as-is. Add GSAP only for the deal animation (card flying sequence) and trick pile card spread. Best of both — no migration risk.

B

GSAP replaces deal + trick animations

Replace the DealAnimation component and TrickPile card entrance animations with GSAP timelines. Smoother sequencing, card-count-driven timing. Framer Motion stays for everything else (panels, badges, overlays).

C

Keep Framer Motion, just fix the bugs

Don't introduce GSAP at all. Fix the timing bug in the existing Framer Motion deal animation. Simpler, no new dependency, fewer risks.

💡 Recommendation: Option B — GSAP timelines are purpose-built for card-count-driven sequences. The deal animation especially benefits from gsap.timeline() which can stagger cards by index, not by wall-clock time.
